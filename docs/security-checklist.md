## Acceptance mapping (ticket #29)

- "Every §17 item checked with a link to test or documented manual evidence" → table above; CI `checklist` job fails if a row loses its evidence link.
- "XSS payloads in rich text and answers neutralized (test suite)" → s17-04 + s17-04a.
- "SSRF: webhook delivery to 169.254.169.254 / 10.x / localhost blocked (test)" → s17-07 (`ssrf-guard.test.ts`).
- "Workspace export + deletion flows work e2e; deleted data purged within retention window" → s17-11 (route-level e2e in `gdpr-routes.test.ts`; browser-level spec `apps/web/e2e/gdpr-abuse.spec.ts` — written, requires a deployed app + DB to run); purge timing enforced by `purgeExpiredWorkspaces` grace window + `purge-retention` job.
- "Restore runbook executed once against a backup (recorded)" → s17-12 (CI drill; staging operator drill pending live infra).

## Honest-gaps register (for the tech lead)

1. **argon2id**: scrypt ships (memory-hard, constant-time verify) behind the `PasswordHasher` seam; swap needs a native build toolchain in the deploy image (one-line container change). Tracked as the only ⚠️ row.
2. **Per-process rate limiters** (ingest + abuse intake) are in-memory seams; multi-instance deploys need the Redis limiter swap (INTEGRATION-DEBT noted in `apps/web/app/api/public/ingest/_lib/deps.ts`).
3. **Physical restore (WAL roll-forward)** and the staging drill against a real nightly backup need live infrastructure — documented operator steps in the runbook.
4. Publish warnings surface in the API response (`PublishOutcome.warnings`); a builder UI banner is not wired (service + test evidence only).
5. Webhook **signing/verification** (HMAC + 5-min timestamp tolerance) is test-backed (s17-07); endpoint-secret **minting** (`randomBytes(32)` at endpoint creation) rides the webhook management API/UI (T26) — the delivery plane signs with whatever reveal-once secret is stored (`packages/db/src/repositories/webhooks.ts`), and other minted credentials (sessions, API tokens) already use 256-bit entropy.
