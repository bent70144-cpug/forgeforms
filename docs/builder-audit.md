# Builder B0 baseline audit (`docs/builder-audit.md`)

Milestone **B0** (builder spec §17, §20, §25): walk §2–§16 of the builder spec against the
current code and record pass/fail per section. Every status below is backed by code evidence
(file paths + what was actually verified), not by wave reports. Audit performed on branch
`feat/builder-milestones`, wave 3b (task 9-b).

Status vocabulary: **PASS** (implemented + verified against the code), **PARTIAL** (implemented
with named gaps), **FAIL** (required piece missing), **UNTESTED** (exists but could not be
exercised here). The unit/component suite is green at audit time: **837/837 tests pass**
(`pnpm --filter @formforge/web test`).

environment (no Lighthouse, no Playwright browsers, no browser profiler); the numeric budgets

| §13 budget | Static assessment | Technique applied (evidence) |
|---|---|---|
| Builder route interactive < 3 s (50-block doc) | not measured | Route is a thin server shell (`app/(app)/d/[docId]/page.tsx`) + one client bundle; the heaviest dependency (conversational renderer) is code-split out (see JS-budget row). |
| Keystroke → canvas update < 16 ms | not measured; render fan-out bounded | `editorReducer` applies ops immutably; only `Canvas` subscribes to full state; cards are `React.memo` so a keystroke on one block re-renders that card + chrome, not siblings (`BlockCard.tsx` — `memo(BlockCardImpl)`; `UnknownBlock` memoized too). Techniques checklist (§13 "Techniques" list):

- Per-block memoization — **done**: `BlockCard = memo(...)` keyed by block reference + primitives; `Canvas` threads a memoized `CanvasActions` object + `referencedIds` (useMemo) and keeps callbacks stable via a `stateRef`, which is what makes card memo effective (`Canvas.tsx`).
- Selector-based store subscriptions — **partially done (this audit's edit)**: the store is React context over `useReducer`, so any state change re-renders every `useBuilder()` consumer. Added a split dispatch context (`context.tsx`: `BuilderDispatchContext` + `useBuilderDispatch()`), and migrated the two genuinely dispatch-only consumers (`UndoToast.tsx`, `settings-helpers.ts` `useDebouncedPatch`) so they no longer re-render on document/selection/save changes. Full selector subscriptions (`useSyncExternalStore` + selector per field) need the store lifted out of `useReducer` — documented as a follow-up, not a small safe change.
- Virtualized left tree above 200 blocks — **not implemented** (`BlocksTree.tsx` renders the full flat row model). Follow-up.
- Lazy-load heavy editors on first use — **not needed today**: no Tiptap/monaco-class editor exists in the builder (§9.4 FAIL); registry editors are plain inputs. Revisit with Tiptap.
- Debounce text inputs — **done**: settings/theme/endings text inputs debounce 300 ms with coalesce keys (`useDebouncedPatch`, `ThemePanel` `THEME_HEX_DEBOUNCE_MS`, `EndingsPanel` `ENDING_EDIT_DEBOUNCE_MS`); the autosave queue itself debounces 500 ms / 5 s max.
- `content-visibility: auto` on off-screen blocks — **done**: every card renders `style={{ contentVisibility: "auto", containIntrinsicSize: "80px" }}` (`BlockCard.tsx`).
- Hard limits (≤ 500 blocks, ≤ 1 MB JSON, insertion disabled with explanation) — **not implemented** client-side; the server still validates the 1 MB/413 path. Follow-up.

## 4. Follow-ups (ordered by data-loss risk, §20 guidance)

1. **Execute the e2e suites on a browser-capable runner** (§16, B2/B8 acceptance). The never-lose-work story (offline kill → reconnect flush, reload → restore prompt, two-tab 409 → rebase/dialog) is unit-tested with fake timers but has never run against a real browser in this environment. Until CI runs `apps/web/e2e/builder.spec.ts` + `a11y-*.spec.ts`, the strongest guarantees are integration-level only.
2. **Route stale offline batches into the §7.3 conflict flow** (`wiring.planRecovery` "discard-stale"). Today a record written against an older rev can only be Discarded — a user can lose a session's edits the spec would have offered to merge. Small, contained change in `planRecovery` + RestorePrompt.
3. **401 re-auth handling in the autosave loop** (§7.1). Pending ops survive, but the user gets a generic "Couldn't save — Retry" with no re-login modal that resumes the session; long-lived sessions silently degrade to offline mode. Detect `status === 401` in `AutosaveController`, park the queue, prompt, resume on re-auth.
4. **Add the missing publish-gate codes FORM_EMBED_MISSING + MISSING_ASSET** (§8.1/B7). Without them a form can publish with a `form-embed` pointing at an unpublished/deleted document or a deleted asset — broken live forms, discovered only by respondents.
5. **Slug availability endpoint + inline "taken" suggestion** (§6.6/§22.1, §14). `GET /api/v1/documents/:id/slug-check` does not exist; today a colliding slug surfaces only as a publish/save failure. Add the route + debounced probe + `-2` suggestion (format validation already exists).
6. **`text` block + Tiptap rich text** (§9.4/§9.2). The palette offers `text`, but it renders as UnknownBlock on canvas (no registry def) and stores a plain string; the allowlist sanitizer already exists in core. Land the registry def + Tiptap editor (lazy-loaded per §13) or remove `text` from the palette until it exists.
7. ~~dnd-kit pointer/touch drag~~ — **DONE (§6.2 follow-up #7)**: pointer/touch drag with ~8 px activation constraint, drop indicator, auto-scroll, Esc-cancel, single coalesced `block.move` on drop and reuse of the `announce()` seam. Deviation: built on native Pointer Events (`useDragReorder.ts`) because `@dnd-kit/*` is not in the frozen lockfile (no new deps) — dnd-kit could later replace the hook without touching the DOM contract or dispatch path. Still open: the §13 drag-budget profiling pass (needs a browser-capable runner).
8. **Entitlements surface for the builder** (§24): resolve `can()` client-side (permissions on the GET envelope) so `remove_branding`, `file_upload_max_mb`, `custom_redirect`, `notify_emails_limit` are real gates instead of the current static §24 placeholders, and 402/403 answers get inline explanations (§14).
9. **Telemetry sink + builder events** (§15): replace the console stub with a real collector and instrument the §15 vocabulary (`autosave_ok {opsCount, ms}` first — it is the autosave-health signal the spec calls out).
10. **Builder hard limits + perf headroom** (§13/§14): 500-block/1 MB insertion guard with explanation; virtualize `BlocksTree` above ~200 rows; shared option-list keyboard interactions (Enter-add, Backspace-delete, paste-split, duplicate warning) per §9.3.
