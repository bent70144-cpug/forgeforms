     1→# FormForge — Build Specification (spec.md)
     2→
     3→> Implementation-ready spec for building FormForge: a multi-tenant SaaS for **forms, landing pages and portfolios** on one block-document model.
     4→> Audience: a developer or coding agent. Follow milestones in order. Every milestone ends with acceptance criteria that must pass before moving on.
     5→> Companion: the "FormForge — SaaS System Design" doc (architecture rationale). This file is the *what to build and how*.
     6→
     7→---
     8→
     9→## 0. How to use this spec
    10→
    11→1. Read sections 1–6 once (stack, layout, conventions, data model, block schema).
    12→2. Build milestones **M0 → M8** (section 15) in order. Do not start a milestone until the previous one's acceptance criteria pass.
    13→3. When this spec and your instinct disagree, follow the spec and leave a `// SPEC-NOTE:` comment explaining the deviation.
    14→4. Anything marked **(Phase 2)** is out of scope until all of M0–M8 are done.
    15→5. Keep modules decoupled: a module may only call another module through its `index.ts` public interface, never its internals or its tables.

    92→### 3. Module contract
    93→
    94→Each module in `packages/core/src/<module>/` exposes only `index.ts` with:
    95→- **Service functions** (`createDocument`, `publishDocument`, ...) taking a `Ctx` as first argument.
    96→- **Types** and **error classes**.
    97→
    98→```ts
    99→// packages/core/src/shared/ctx.ts
   100→export type Ctx = {
   101→  workspaceId: string;
   102→  actor: { type: "user" | "token" | "mcp" | "system"; id: string };
   103→  requestId: string;
   104→  now: () => Date;
   105→};
   106→```
   107→
   108→Rules:
   109→- Every service function that touches tenant data **requires** a `Ctx` and scopes queries by `ctx.workspaceId`. A function without a `Ctx` cannot read tenant tables.
   110→- Services return `Result<T, AppError>` (no thrown errors across module boundaries except for programmer errors).
   111→- Repositories live in `packages/db`; only the owning module imports its repositories.
   112→- Side effects (email, webhooks, analytics) are enqueued, never executed inline in request handlers.

   116→## 4. Conventions
   117→
   118→**IDs:** UUIDv7, generated in the app (`uuidv7()`), stored as `uuid`. Public IDs in URLs use a prefix + base58 short form (`doc_…`, `sub_…`, `ast_…`) produced by a `shortId` helper in `shared/ids.ts`. Never expose sequential IDs.
   119→
   120→**Time:** stored as `timestamptz` in UTC. Use the injected `ctx.now()`, never `new Date()` inside services (testability).
   121→
   122→**Errors:** one `AppError` class with `code` (`NOT_FOUND`, `FORBIDDEN`, `VALIDATION`, `CONFLICT`, `RATE_LIMITED`, `PLAN_LIMIT`, `INTERNAL`), `message`, `details`. API maps codes to HTTP status (404, 403, 422, 409, 429, 402, 500).
   123→
   124→**API error body:**
   125→```json
   126→{ "error": { "code": "VALIDATION", "message": "Invalid input", "details": [{ "path": "blocks[2].props.title", "message": "Required" }] } }
   127→```
   128→
   129→**Pagination:** cursor-based. `?limit=50&cursor=<opaque>` → `{ data: [...], nextCursor: string | null }`.
   130→
   131→**Idempotency:** mutating public endpoints accept `Idempotency-Key`. Keys stored in Redis for 24h; a repeated key returns the original response.
   132→
   133→**Logging:** structured JSON (`pino`), always include `requestId`, `workspaceId`, `documentId` when known. Never log answer values, passwords, tokens.
   134→
   135→**Feature gating:** one function only: `can(workspaceId, capability): Promise<boolean>` in `billing`. No inline plan checks anywhere else.
   136→
   137→**Naming:** files `kebab-case.ts`, React components `PascalCase.tsx`, DB columns `snake_case`, TS fields `camelCase` (Drizzle mapping).

   186→

   188→

   190→-- identity & tenancy
   191→create table users (
   192→  id uuid primary key,
   193→  email citext unique not null,
   194→  name text,

   196→  email_verified_at timestamptz,
   197→  created_at timestamptz not null default now()
   198→);
   199→
   200→create table workspaces (
   201→  id uuid primary key,
   202→  name text not null,
   203→  slug text unique not null,
   204→  plan text not null default 'free',            -- free | pro | business
   205→  stripe_customer_id text,
   206→  stripe_subscription_id text,
   207→  created_at timestamptz not null default now()
   208→);
   209→
   210→create table memberships (
   211→  workspace_id uuid references workspaces(id) on delete cascade,
   212→  user_id uuid references users(id) on delete cascade,
   213→  role text not null,                            -- owner | admin | editor | viewer
   214→  primary key (workspace_id, user_id)
   215→);
   216→
   217→create table api_tokens (
   218→  id uuid primary key,
   219→  workspace_id uuid not null references workspaces(id) on delete cascade,
   220→  name text not null,
   221→  token_hash text not null unique,               -- sha256; plaintext shown once
   222→  scopes text[] not null,                        -- docs:read docs:write docs:publish submissions:read
   223→  last_used_at timestamptz,
   224→  created_at timestamptz not null default now()

   226→
   227→-- documents

   366→## 7. Block document schema (Zod)
   367→
   368→Defined in `packages/schema/src/document.ts`. This is the heart of the product.
   369→
   370→```ts
   371→import { z } from "zod";
   372→
   373→export const BlockBase = z.object({
   374→  id: z.string().min(1),          // stable, nanoid(10)
   375→  kind: z.string(),
   376→  props: z.record(z.unknown()),   // validated by the kind's own schema
   377→  children: z.array(z.lazy(() => Block)).optional(),
   378→  hidden: z.boolean().optional(),
   379→});
   380→export type Block = z.infer<typeof BlockBase>;
   381→export const Block: z.ZodType<Block> = BlockBase;
   382→
   383→export const Theme = z.object({
   384→  tokens: z.record(z.string()),    // e.g. "color.bg": "#fbf9f4"
   385→  fontHeading: z.string().default("Inter"),
   386→  fontBody: z.string().default("Inter"),
   387→  radius: z.enum(["none", "sm", "md", "lg", "full"]).default("md"),
   388→});
   389→
   390→export const Rule = z.object({
   391→  id: z.string(),
   392→  scope: z.string(),               // blockId this rule runs after, or "start"
   393→  when: z.array(z.object({
   394→    left: z.string(),              // "@block:<id>" | "@var:<name>" | "@hidden:<name>"
   395→    op: z.enum(["eq","neq","gt","gte","lt","lte","contains","isEmpty","matches"]),
   396→    right: z.unknown().optional(),
   397→  })),
   398→  then: z.array(z.discriminatedUnion("type", [
   399→    z.object({ type: z.literal("goto"), target: z.string() }),       // blockId | "end:<endingId>"
   400→    z.object({ type: z.literal("set"), var: z.string(), value: z.unknown() }),
   401→  ])),
   402→  isFallback: z.boolean().default(false),   // "in all other cases"
   403→});
   404→
   405→export const DocumentBody = z.object({
   406→  schemaVersion: z.literal(1),
   407→  type: z.enum(["form", "page", "portfolio"]),
   408→  theme: Theme,
   409→  settings: z.object({
   410→    seo: z.object({ title: z.string().optional(), description: z.string().optional(), ogImageAssetId: z.string().optional() }).default({}),
   411→    locale: z.string().default("en"),
   412→    progressBar: z.boolean().default(true),
   413→    autoAdvance: z.boolean().default(true),
   414→    showBranding: z.boolean().default(true),
   415→    captcha: z.boolean().default(false),
   416→    closeAt: z.string().datetime().optional(),
   417→    maxSubmissions: z.number().int().positive().optional(),
   418→    notifyEmails: z.array(z.string().email()).default([]),
   419→  }),
   420→  blocks: z.array(Block),
   421→  endings: z.array(z.object({ id: z.string(), title: z.string(), body: z.string().optional(), redirectUrl: z.string().url().optional() })).default([]),
   422→  logic: z.object({ rules: z.array(Rule) }).default({ rules: [] }),
   423→});
   424→export type DocumentBody = z.infer<typeof DocumentBody>;
   425→```

   427→### 7.1 Block registry
   428→
   429→Each block lives in `packages/blocks/src/<kind>/` with four files:
   430→
   431→```
   432→index.ts      # registers the block
   433→schema.ts     # Zod schema for props (and answer value, for question blocks)
   434→editor.tsx    # builder UI: canvas preview + settings panel
   435→render.tsx    # public renderer component (server-safe; client only if interactive)
   436→```
   437→
   438→```ts
   439→export type BlockDef<P, A = never> = {
   440→  kind: string;
   441→  family: "content" | "question" | "action" | "layout";
   442→  label: string;
   443→  icon: string;
   444→  propsSchema: z.ZodType<P>;
   445→  defaultProps: () => P;
   446→  answerSchema?: z.ZodType<A>;                         // question blocks only
   447→  validate?: (answer: A, props: P) => string | null;   // server-side + client-side
   448→  Editor: React.FC<EditorProps<P>>;
   449→  Render: React.FC<RenderProps<P, A>>;
   450→};
   451→```
   452→
   453→**Registry rules**
   454→- Registry is built at import time; unknown `kind` in a stored document renders as nothing (never crashes).
   455→- Question blocks MUST define `answerSchema`; ingest validates every answer against it.
   456→- Content blocks never store anything in `answers`.
   457→

   494→## 8. Document lifecycle
   495→
   496→```
   497→create → draft ─(edit, autosave)→ draft ─(publish)→ published ─(edit)→ published + unpublished changes
   498→                                                    └─(unpublish)→ draft
   499→```
   500→
   501→**Autosave (authoring)**
   502→- Client sends patches to `PATCH /api/v1/documents/:id` with `{ baseRev, ops: Op[] }`.
   503→- Ops: `block.insert {parentId?, index, block}`, `block.update {id, props}`, `block.move {id, parentId?, index}`, `block.remove {id}`, `settings.update {…}`, `theme.update {…}`, `ending.upsert/remove`, `rule.upsert/remove`, `meta.update {title, slug}`.
   504→- Server applies ops in one transaction against `documents.draft`, validates the result with `DocumentBody`, increments `rev`. If `baseRev !== rev` → `409 CONFLICT` with the current `rev` and body.
   505→- Client debounce 500 ms; queue serializes requests; show "Saving…" / "Saved" indicator; recover from 409 by refetching and re-applying unsent ops where possible.
   506→
   507→**Publish**
   508→1. Validate `draft` fully (`DocumentBody`, lint rules, required assets exist, form-embed targets exist and are published).
   509→2. Insert immutable `document_versions` row with the body.
   510→3. Build snapshot (resolve theme → CSS variable map, asset ids → CDN URLs, compile logic into block-indexed routing map, sanitize rich text) and upsert `snapshots`.
   511→4. Update `documents.status = 'published'`, `published_version_id`.
   512→5. Purge CDN cache by tag `doc:<id>`; update KV routing entry.
   513→6. Return `{ url }`. Target total latency p95 under 10 s.
   514→
   515→**Unpublish:** set `status='draft'`, delete snapshot cache keys; public URL returns the "unavailable" page (HTTP 410).
   516→
   517→**Snapshot shape** (`snapshots.rendered`):
   518→```ts
   519→type Snapshot = {
   520→  documentId: string; versionId: string; type: "form"|"page"|"portfolio";
   521→  title: string; seo: {...}; locale: string;
   522→  cssVars: Record<string,string>;
   523→  blocks: Block[];                       // sanitized, asset URLs resolved
   524→  endings: Ending[];
   525→  routing: Record<string, RouteNode>;    // compiled logic, keyed by blockId
   526→  settings: { progressBar: boolean; autoAdvance: boolean; showBranding: boolean; captcha: boolean; closeAt?: string };
   527→};
   528→```

   531→
   532→## 9. Logic engine (`packages/core/src/logic`)
   533→
   534→Pure functions, zero I/O, no framework imports. Used by the renderer (client), ingest validation (server) and tests.
   535→
   536→```ts
   537→export function compile(rules: Rule[], blocks: Block[]): Routing;   // lint + index
   538→
   539→export function evaluate(
   540→  routing: Routing,
   541→  ctx: { answers: Record<string, unknown>; variables: Record<string, unknown>; hidden: Record<string, unknown>; currentBlockId: string }
   542→): { nextBlockId: string | `end:${string}`; variables: Record<string, unknown> };
   543→```
   544→
   545→**Semantics**
   546→- Default next = the next question block in document order; after the last, `end:<first ending>`.
   547→- Rules scoped to `currentBlockId` are evaluated in array order; first rule whose `when` conditions all pass (AND) wins; its `then` actions run in order.
   548→- A rule with `isFallback: true` has empty `when` and runs only if no other rule matched.
   549→- Unknown `goto` target at runtime → fall back to default next (never crash).
   550→- Operand resolution: `@block:<id>` → answer value (normalized: select → optionId, rating → number), `@var:<name>`, `@hidden:<name>`.
   551→
   552→**Compile-time lint (blocks save/publish on error):** dangling `goto` targets, rules scoped to missing blocks, goto cycles with no exit, more than one fallback per scope.
   553→
   554→**Tests:** table-driven golden cases in `logic/__tests__/cases/*.json`, at least 40 cases covering every operator, fallback, missing answers, and cycle detection.

   575→
   576→- **Scroll renderer** (pages, portfolios): server components. Static HTML, hydrate only interactive blocks (`form-embed`, gallery lightbox).
   577→- **Conversational renderer** (forms): client bundle, one question at a time, progress bar, up/down arrows, auto-advance on select/rating/NPS (under 300 ms), keyboard: Enter advances text, Ctrl/Cmd+Enter advances long text and choice, Shift+Enter newline.

   582→### 10.3 Ingest contract
   583→
   584→**Start** — `POST /api/public/submissions`
   585→```json
   586→{ "documentId": "doc_…", "hidden": { "utm_source": "x" }, "turnstileToken": "…" }
   587→```
   588→→ `201 { "token": "sub_…", "versionId": "…" }`
   589→Rules: document must be `published`, not past `closeAt`, under `maxSubmissions`; verify Turnstile when `captcha` is on; create `draft` submission; emit `start` event.
   590→
   591→**Save step** — `PATCH /api/public/submissions/:token`, header `Idempotency-Key`
   592→```json
   593→{ "answers": [{ "blockId": "b3", "value": "ana@example.com", "clientTs": "2026-11-06T10:00:00.000Z" }] }
   594→```
   595→→ `200 { "next": "b4", "variables": { … } }`
   596→Rules: validate each answer with the block's `answerSchema` + `validate`; upsert per answer only if `clientTs > answers.updated_at`; compute `next` via the logic engine; reject when the submission is not `draft`.
   597→
   598→**Complete** — `POST /api/public/submissions/:token/complete`
   599→```json
   600→{ "answers": [ /* client's final value for every touched block */ ] }
   601→```
   602→→ `200 { "endingId": "end_1", "redirectUrl": null }`
   603→Rules: reconcile (upsert all provided answers, last client value wins), validate required blocks reachable by the logic path, set `completed`, emit `complete`, enqueue `submission.completed` event, increment usage counter. Idempotent: a second call returns the same result.
   604→
   605→**Limits:** per-IP 60 requests/min on start, per-token 120/min on save; payload ≤ 256 KB; honeypot field `_hp` must be empty (silently mark `spam` if not).

   642→## 12. Background jobs (BullMQ)
   643→
   644→| Queue | Job | Trigger | Behavior |
   645→|---|---|---|---|
   646→| `events` | `submission.completed` | ingest complete | Fan-out: notification email, webhooks, analytics |
   647→| `email` | `send-notification`, `send-export-ready`, `send-verify`, `send-reset` | various | Resend; retry 5× exponential |
   648→| `webhooks` | `deliver` | fan-out / replay | POST with signature; backoff 1m, 5m, 30m, 2h, 12h; log every attempt; disable after 10 consecutive failures |

   651→| `analytics` | `ingest-batch`, `rollup` | beacon / cron | Insert events; rollup daily (hourly for today) |
   652→| `maintenance` | `reap-orphans`, `purge-old-deliveries`, `create-partitions` | cron | Housekeeping |

   654→**Webhook payload & signature**
   655→```json
   656→{ "id": "evt_…", "type": "submission.completed", "occurredAt": "…", "workspaceId": "…", "documentId": "…",
   657→  "data": { "submissionId": "…", "answers": { "<blockId>": { "label": "Email", "value": "…" } }, "hidden": {}, "variables": {} } }
